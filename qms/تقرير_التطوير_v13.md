# v13 — منصة مسارات التصنيع

الاختبارات: `python -m unittest discover -s tests -v` (13 اختبارًا: التدفق القديم + المسارات الثلاثة). الترحيل من v11/v12 تلقائي ولا يغيّر أي سجل أو رقم تشغيلة.

## 1) المعمارية (لا `if product == …` في الشاشات)
```
Product (items.route_code)  ←  Route (routes)  ←  Route Steps (route_steps: مسار × معقم/غير معقم)
        ←  QC Gates (qc_templates.mfg_routes / requires / is_final)  ←  Inventory Tx (stock_tx)
```
- `mfg.py`: المسارات، الخطوات، **معالجات التقدّم** (`@step('BMACH')`…)، المخرجات (سليم/مرفوض/هالك)، الإفراج النهائي، مرحلة WIP الأخيرة.
- `inventory.py`: دفتر حركات؛ كل انتقال **قيدان متلازمان** بتعامل واحد، ولا خروج أكبر من الرصيد ← لا تُوجد الكمية في مرحلتين معًا.
- إضافة مسار جديد = صفوف في `routes` + `route_steps` (+ معالج تقدّم إن لزم) + نماذج جودة بمسارها؛ بلا برمجة قوائم عامة.
- بيانات لا كود: فئات الخام `mat_classes`، بنود فحص الخام `rm_checks`، تكوين التعبئة `pack_config`، أحرف الترقيم في `routes`.

## 2) المسارات
| المسار | الرمز | الخطوات |
|---|---|---|
| تصنيع الشاش من الرول الخام | `FULL_GAUZE` | كما هو (استلام ← فحص ← أسليتر ← سب رول ← طي ← [فرز ← تغليف أولي ← تعقيم] أو [تغليف] ← فحص نهائي ← مخزن) |
| الشاش نصف المصنع | `SP_GAUZE` | غير معقم: تخصيص SP ← تعبئة (قطعة/باك/بوكس/كرتون) ← فحص نهائي ← مخزن · معقم: تخصيص ← فرز ← تعبئة أولية ← تعقيم ← فحص/إفراج ← مخزن |
| الرباط الضاغط | `BANDAGE` | جامبو ← تخصيص ← ماكينة الأربطة ← تغليف ← بوكسات ← كراتين ← فحص نهائي ← مخزن (غير معقم) |

**تحديد المسار تلقائيًا:** المسار مرتبط بالصنف في «بيانات المنتجات». شاشة أمر الإنتاج تعرضه وخطواته وتحذيرات الجاهزية بمجرد اختيار الصنف، ولا يختاره المستخدم. تغييره الاستثنائي لمن يملك `route_override` (المدير) بسبب إلزامي وتسجيل في التدقيق. الأمر يحفظ مساره وقت إصداره.

### SP
- **استلام** `/sp/receive`: المورد، PO، لوط المورد، الدفعة الداخلية (`SPR-…`)، المقاس/الطبقات/الكاشف من الصنف، الكمية، الوحدة، عدد الأكياس، تواريخ، COA، المستلم، موقع المخزن ← حالة «حجر / Pending QC» + إشعار للجودة.
- **الفحص** بنفس شاشة الاستلام/الفحص مع بنود خاصة بـ SP (`rm_checks`) ← قبول/رفض/معلّق ← إشعار للإنتاج عند الإفراج.
- **التخصيص**: لا يقبل خامًا غير مفرج، ولا غير مطابق للصنف (مقاس/طبقات/كاشف/ميش)، ولا منتهي الصلاحية، ولا أكثر من المتاح أو من احتياج الأمر.
- **رصيد اللوط** `/sp/lots`: مستلم / مصروف / سليم / مرفوض / هالك / متبقٍ. (عند تغذية أمر من عدة لوطات يُوزَّع الناتج بنسبة المصروف.)
- **التعبئة غير المعقمة**: الباكات والبوكسات والكراتين من `pack_config` (لا أرقام في الكود) مع رفض الكسر إن لم يسمح المستوى بعبوة جزئية.
- **المعقم**: يستعمل شاشات الفرز والتغليف والتعقيم القائمة؛ التخصيص يُنشئ «كرتونة مصدر» بلا طي، وحركات الفرز والتغليف تُقيَّد في دفتر المخزون.
- التتبع: `منتج نهائي ← تعقيم/تعبئة ← تخصيص ← لوط SP ← استلام ← لوط المورد ← المورد`.

### الرباط الضاغط
- **جامبو رول**: استلام عبر `receipts/new?cls=JUMBO` (الطول إلزامي، الرصيد بالمتر) ← Pending QC ← فحص/إفراج.
- **تخصيص**: جامبو مفرج فقط، عرضه ≥ عرض المنتج.
- **ماكينة الأربطة**: الأمر، الدفعة، الجامبو، العرض، مدخل (م/كجم)، عدد رولات، طول الرول، مرفوض، هالك، مشغّل، ماكينة، بدء/انتهاء، تاريخ، ملاحظات. لا مدخل أكبر من متبقي الجامبو، ولا ناتج يفوق المدخل (تسامح 2% قابل للتعديل `bandage_yield_tolerance_pct`).
- **التغليف** لا يقبل إلا من ناتج ماكينة فعلي وبقدر المتاح؛ **البوكسات** و**الكراتين** من `pack_config` مع الجزئي حسب السماح.
- كل مرحلة سند فرعي `الأمر/BM01 ← BW01 ← BX01 ← CT01` يحمل أبوه؛ الفحص النهائي والإفراج بنماذج خاصة (`QC-BND-*`, `QA-BND-REL` نهائي).
- تتبع عكسي: من الجامبو أو لوط المورد إلى كل المنتجات النهائية والعملاء (`/genealogy?ref=`).

## 3) ما يربط المسارات (نفس الأنظمة)
- **أوامر الإنتاج** بمسار وتقدّم حقيقي (خطوات كل مسار)، **الجودة** بمسارات تطبيق لكل نموذج (`mfg_routes`) وشروط إفراج تتجاوز ما لا ينطبق، **NCR**، **التدقيق**، **المخزن** (استلام المنتج التام بعد الإفراج فقط ← يفرّغ WIP، والشحن من رصيد المخزن).
- **الإشعارات** `/notifications` + جرس: استلام خام (رولات/SP/جامبو) ← الجودة · إفراج الخام / أمر إنتاج / تخصيص / اكتمال مراحل / اكتمال الإنتاج ← الإنتاج والجودة · إفراج نهائي ← المخزن · NCR ← الجودة والمدير. الاستهداف بالصلاحية وبخطوط المستخدم؛ القراءة لكل مستخدم.
- **لوحة المدير** بكرت لكل خط (أوامر فعّالة، بانتظار الجودة، WIP، منجز اليوم، أُفرج اليوم، مرفوض/معلّق) وصفحة تفصيل لكل خط `/line/<route>`.
- **WIP** `/wip` و**المنتجات النهائية** `/fg`.
- **تقرير الأصل والفرع** `/genealogy` (خط زمني + شجرة أصل + مصادر الخام والمورد + الكميات والمرفوض والهالك + الجودة والإفراج والمخزن والشحن) يعمل للمسارات الثلاثة، وتحويل `/trace` لأوامر SP/الرباط إليه تلقائيًا.

## 4) القوائم والصلاحيات
- قائمة شجرية: الإنتاج (شاش كامل / SP / رباط / متابعة) · المخزن · الجودة (مهام، فحص خام حسب الفئة، أثناء الإنتاج، نهائي حسب المسار، إفراج، NCR، سجل، قوالب) · التتبع · الإدارة — **لا يظهر إلا ما يملكه المستخدم وما يعمل على خطه**.
- **خطوط الإنتاج لكل مستخدم** (`users.lines`): مشغّل SP لا يصل لشاشات الرباط ولا لقائمته ولا لإشعاراته (403).
- دور جديد «أمين مخزن» (استلام الخام + مخزن المنتج التام). الشحن يتطلب الآن استلام المخزن أولًا.

## 5) بيانات مبدئية يجب أن تراجعوها
1. **أصناف SP**: كل الشاش التام الحالي (`GS*`) مساره `FULL_GAUZE` افتراضيًا. حدّدوا من «بيانات المنتجات» (تحديد جماعي) الأصناف التي مسارها SP. لوط SP يطابق الصنف بـ(المقاس، الطبقات، الكاشف، الميش).
2. **أصناف الرباط الضاغط** `CB005 / CB075 / CB100 / CB150` **مؤقتة** (كود ووصف) بتكوين تعبئة تجريبي (10 رول = بوكس، 10 بوكس = كرتون) — عدّلوها أو احذفوها؛ يمكن إضافة أي مقاس آخر.
3. **تكوين التعبئة لأصناف SP** غير معرَّف: لا تعبئة غير معقمة قبل تعريفه.
4. نماذج جودة الرباط وحدودها مبدئية (سماحية العرض 0.4 سم كما في الشاش، طول الرول اختياري) — تُعدَّل من القوالب.

## 6) حدود هذه المرحلة (بصراحة)
- WIP مسار **الشاش الكامل مشتق** من سندات الطي/الفرز/التغليف القائمة (لا قيود مخزون لها) حفاظًا على البيانات والتقارير الحالية؛ مساراً SP والرباط من **دفتر المخزون** مباشرة، والمنتج التام لكل المسارات من الدفتر.
- خطوات المسارات تُعدَّل من قاعدة البيانات (شاشة المسارات عرض فقط حاليًا).
- «مواد التغليف المستخدمة» في تغليف الرباط تُسجَّل نصًا (بلا خصم مخزون).
- لا إبطال/تصحيح لسندات الإنتاج (طي/فرز/تغليف/مراحل الرباط) بعد.
