# تقرير التطوير — الإصدار 15 («التتبع الكامل»)

الهدف: تثبيت **التتبع الكامل (Traceability)** وربط كل مرحلة بمخرجات المرحلة السابقة، مع أقل إدخال يدوي. لم يُعَد بناء المشروع؛ v15 فوق v14 بترحيل آمن قابل للتكرار (`migrate_v15.py` — إضافات فقط، لا حذف بيانات).

> **الورق الرسمي:** اعتُمد ملف شركة أتاكم الخير المرفق (خلفية A4 بترويسة وتذييل) وهو مُضمَّن افتراضيًا؛ يمكن استبداله من **الإعدادات ← الورق الرسمي**. الطباعة بخط Times New Roman حجم 12، هامش علوي 46 مم وسفلي 32 مم (يتجاوزان الترويسة والتذييل)، و«Page X / Y» تحت خط الترويسة. تحققت من ملف PDF ناتج فعليًا.

**قرارات الإدارة المطبّقة بعد المراجعة:** (1) عند اختلاف مصفوفة القص عن عرض Sub Roll في Excel يُعتمد **الأصغر** (43 بدل 44، 25.5 بدل 26.5) فصار لكل المنتجات Sub Roll مطابق. (2) الكراتين **يدوية** (لا تُشترط باكت/كرتون ولا بوكس/كرتون). (3) الوحدة الأساسية: باكت (100 مسحة) لغير المعقم، بوكس (100 مسحة) للمعقم، بوكس الأربطة = **12 رباطًا**. (4) حد الهدر **3%**. (5) **SP الوارد من مورّد** يدخل مباشرة كمصدر مسحات لأي أمر شاش (معقم أو غير معقم) من صفحة الأمر ← «استخدام SP وارد»: غير المعقم يذهب للتعبئة، والمعقم يصير كرتونًا وسيطًا (`SUPPLIER_RECEIPT`) بانتظار إفراج SP ثم سجل الفرز والتغليف؛ كود SP من Master Data لا يُخترع، ويُتتبَّع لوط المورّد. (6) حُذف الملف الكبير من تاريخ Git.

## 1) ما بُني (مقابل بنود الطلب)

| البند | ما أُنجز |
|---|---|
| **مصدر Master Data = Excel** | أكواد Sub Roll (SR) وأكواد SP وأكواد التعبئة تُقرأ من الملف؛ العرض المرجعي للرول/السب رول يُستخرج من نص الوصف («120 Cm») دون تعديل الوصف. لا كود ولا مواصفة مخمَّنة (الكود لا يُحلَّل أبدًا). |
| **مركز التتبع** (`/trace/center`) | بحث بأي معرّف: باركود، لوط مورّد، جامبو، رقم رول المورد، سب رول، تشغيل قص، سند طي، أمر، تشغيلة، كرتون SP، سجل فرز/تغليف، دورة تعقيم، سند تعبئة. **خلفيًا:** المنتج ← الطي ← السب رول ← الجامبو ← لوط المورد. **أماميًا:** لوط/جامبو/سب رول ← كل الطي والتعبئة والدورات والمنتجات. |
| **الاستخدام المزدوج** | الجامبو: Available ← Allocated ← In Slitting ← Consumed بمطالبة ذرية `UPDATE … WHERE status=…` + فهارس فريدة؛ السب رول مرة واحدة برسالة «تم استخدام هذا Sub Roll مسبقا في سند رقم XXXXX.». اختُبر بـ 4 نوافذ متزامنة: ينجح واحد فقط. |
| **سند السليتر** | الجامبو (بالمسح أو الاختيار)، العرض/الطول المرجعي مقابل الفعلي، المشغّل من قائمة، رقم التشغيل تلقائي بنظام الترقيم القائم (`SEP-2629-SL-001`)، لوط المورد ورقم رول المورد يُنقلان تلقائيًا. |
| **كود Sub Roll** | من ملف Excel فقط: واحد مطابق ← تلقائي؛ عدة مطابقات ← تظهر المطابقة فقط؛ لا مطابق ← «لا يوجد Sub Roll مطابق لمواصفات المنتج. يرجى مراجعة Master Data» + اختيار يدوي (يُسجَّل `sr_manual`). |
| **بطاقة Sub Roll** | باركود Code128 = معرّف السب رول الفريد، وكود الماستر، رقم التشغيل، الأمر، الجامبو المصدر، لوط المورد، العرض/الطول، الحالة «جاهز للطي»، التاريخ، المشغل. زر «طباعة البطاقات» بعد القص. |
| **المشغلون** | قائمة رئيسية (إنتاج/تعقيم…) تُدار من **الإدارة ← المشغلون**؛ لا نص حر في شاشات الإنتاج. قائمة التعقيم: محمد السعيد / عبد الوهاب صابر. |
| **سند الطي** | مسح/اختيار السب رول، جلب الأمر والمنتج والماكينة (Machine 10 لـ 10×10) والتشغيلة تلقائيًا. **المخرج = مسحات سليمة (وليس باكت)**. النظري = الأبعاد الفعلية للسب رول ÷ استهلاك المسحة القياسي؛ الهدر = النظري − السليم؛ الهدر % وYield % حيّان أثناء الكتابة؛ تحذير عند تجاوز حد الهدر. |
| **تعديل/حذف** | التعديل (كمية، وحدة مسحة/باكت/بوكس، مشغل، سب رول) يُعيد الحساب والمخزون. الاعتماديات: لا خفض تحت ما عُبّئ ويُذكر السند المطلوب عكسه؛ سحب قرار الجودة يحتاج تأكيدًا؛ الحذف = **Reversal** (السب رول يعود متاحًا، قيود عكسية في دفتر المخزون بلا تكرار). مدير النظام يعدّل بعد الاعتماد (يُسحب القرار) ولا يعدّل بعد التخزين. |
| **غير المعقم** | ... ← مسحات ← **تعبئة** (100 مسحة = باكت، ثم كراتين حسب Packaging Configuration) ← إفراج نهائي ← مخزن. الوحدة التجارية: باكت. |
| **المعقم** | طي ← كرتون وسيط SP (باركود `SPC-000001`، كود SP من Master Data، `INTERNAL_PRODUCTION`/`SUPPLIER_RECEIPT`) ← إفراج SP ← **سجل موحّد** (فرز وعد ← تغليف (مغلف 5/10) ← بوكس 100 ← كراتين) ← إفراج قبل التعقيم ← **دورة تعقيم** متعددة اللوطات (رقم تلقائي، مسؤول من قائمة، غرفة، بداية/نهاية) ← التهوية ← تحقق الفعالية (CI/BI) ← إفراج نهائي ← مخزن. رقم اللوط ورقم الدورة يُطبعان على المغلف/البوكس ويُحفظان روابط في القاعدة. |
| **الإفراجات الخمسة فقط** | خام/جامبو · منتج غير معقم · SP · قبل التعقيم · نهائي معقم. سجلات المتابعة **لا توقف سير العمل**. |
| **قوالب وسجلات المتابعة** | قسم مستقل: رقم النموذج، الإصدار، تاريخ السريان (يعدّلها الأدمن)، تاريخ الفحص، القائم بالفحص، التشغيلة، Checklist (مطابق/غير مطابق/لا ينطبق)، ملاحظات، إجراء تصحيحي، اعتماد، طباعة. |
| **Admin Master Data** | تعديل كل شيء بما فيه **اسم الكود**: مفتاح داخلي ثابت `uid` (لا الكود) يربط السجلات؛ تغيير الكود يُحدَّث في كل الجداول في تعامل واحد ويُسجَّل في `item_code_history` والتدقيق. غير الأدمن لا يستطيع. |
| **Packaging Configuration** | صفحة لكل صنف: غير معقم (مسحات/باكت، باكت/كرتون، أكواد) ومعقم (مسحات/مغلف 5\|10، مسحات/بوكس، مغلفات/بوكس تلقائي، بوكس/كرتون، أكواد) مع فلتر «الناقص». |
| **مركز استيراد Excel** | رفع ← أوراق ← معاينة ← ربط أعمدة (تخمين تلقائي) ← تحقق ← كشف تكرار (في الملف وفي القاعدة) ← أخطاء ← استيراد (إضافة جديد / تحديث موجود / كلاهما) + سجل (من، متى، ملف، مضاف/محدَّث/متخطى/مرفوض). أهداف: منتجات، خام، Sub Roll، أكواد تعبئة، مخزون افتتاحي، موردون، ربط منتجات/BOM، Packaging Configuration، Yield، بيانات عامة. |
| **بطاقات المواد** | لأي نوع (خام/تعبئة/نصف مصنع/نهائي/قطع غيار): كود، عربي/إنجليزي، وصف، فئة، وحدة، باركود، تتبع لوط/رول، مورد، حد أدنى، موقع، حالة، ملاحظات + استلام/صرف/تسوية برصيد لا يقبل السالب. |
| **الطباعة** | زر طباعة على: أمر الإنتاج، السليتر، الطي، التعبئة، سجل الفرز والتغليف، دورة التعقيم، الإفراج، سجل المتابعة، حركة المخزون. بطاقات: جامبو، Sub Roll، كرتون SP، باكت، مغلف، بوكس، كرتون، منتج نهائي. RTL، جداول ضمن الصفحة، «Page X / Y»، الورق الرسمي خلفية كل صفحة. الطباعة عبر المتصفح (حفظ PDF) — لا مكتبات PDF على الخادم. |
| **القائمة الجانبية** | شجرة بترتيب سير العمل (الإنتاج ← الشاش ← …، الجودة، المخزون، التقارير، التتبع، الإدارة) تُطوى وتُحفظ حالتها. كل دور يرى وظائفه فقط والباقي **غير موجود** لا معطَّل، والخادم يمنع الرابط المباشر (403). |
| **المظهر** | لوحة جديدة: أخضر مزرق داكن، أيقونات SVG ملوّنة بلون لكل مجموعة (كهرماني/أخضر/سماوي/بنفسجي/وردي)، ترويسة متدرجة، جداول بترويسة داكنة. |

## 2) الاختبارات (15 اختبارًا، كلها ناجحة — `python -m unittest discover -s tests`)

- **GS310M غير معقم حقيقي** من Excel: 500 باكت = 50,000 مسحة ← 10 سب رول ← جامبوهان؛ فلترة Sub Roll: 23 سم + Plain + Mesh 19×15 ← **SR009** تلقائيًا؛ مسح SR ← مسحات سليمة ← النظري 5,000/الهدر 150 (3%) ← 485 باكت ← 24 كرتونًا ← إفراج ← مخزن؛ رصيد المخزون: `NSP_OUT` ثم `FG` بلا بقايا WIP.
- **منتج معقم حقيقي** (GS013M ← SR007 ← SP013M): جامبو ← سليتر ← طي ← `SPC-000001` ← إفراج SP ← فرز 9,700 ← 970 مغلفًا ← 97 بوكسًا ← 9 كراتين ← إفراج قبل التعقيم ← دورة ← تهوية ← تحقق CI/BI ← إفراج نهائي ← مخزن، ولوط الإنتاج ورقم الدورة على بطاقة البوكس؛ **التتبع الأمامي والخلفي لم ينقطع** من السب رول والدورة والجامبو ولوط المورد.
- الاستخدام المزدوج والتوازي، التعديل/الحذف والاعتماديات، تغيير الكود، الاستيراد، الورق الرسمي، الصلاحيات والقائمة لكل دور، حالات الجامبو الأربع، «لا Sub Roll مطابق»، بطاقات المواد، خطا SP والأربطة (لم يتأثرا)، الترحيل، وأن كل الصفحات تفتح.

## 3) تعارضات ونواقص وجدتها في بياناتك — عُرضت كتنبيهات لمدير النظام (**الإدارة ← تنبيهات البيانات**) ولم أخمّن لها قيمًا

1. ~~16 منتجًا بلا Sub Roll~~ — حُلّت باعتماد الأصغر (تظهر ملاحظة المصدر في بيانات الأمر).
2. الكراتين صارت يدوية؛ يبقى مطلوبًا في Packaging Configuration فقط: مسحات الباكت (غير معقم) ومسحات المغلف والبوكس (معقم). (في اختباراتي أدخلت قيمًا تجريبية — مغلف 10 — وهي ليست في بياناتك.)
3. **40 صنفًا بلا خامة (BOM) محددة**: يُقترح الجامبو المطابق للميش والكاشف تلقائيًا.
4. **حد الهدر** 3% (قرارك) وقابل للتخصيص لكل صنف.
5. **إنتاجية السب رول** لـ GS310M (5000 كانت مزروعة في v14) أُلغيت: النظري يُحسب الآن من أبعاد السب رول الفعلية. مثال v14 (5 سب رول لـ 25,000 باكت) كان خاطئًا بالوحدات الصحيحة: 25,000 باكت = 2,500,000 مسحة؛ لذلك اختبرت بـ 500 باكت (50,000 مسحة = 10 سب رول).
6. **Sub Roll لا يحمل عدد الطبقات** في الماستر (ملف SR يميّز العرض/الميش/الكاشف فقط).

## 4) قيود أُفصح عنها

- **الطباعة** عبر نافذة المتصفح (Ctrl+P ← حفظ PDF) لا بمكتبة PDF؛ الترقيم «Page X / Y» يتطلب كروم/إيدج حديثًا (≥131).
- **SP الوارد**: افترضت أن قطعة SP = مسحة واحدة عند الإدخال؛ الخط الخارجي SP القديم بقي كما هو.
- تخصيص **قوالب المتابعة الرسمية** (Slitter/Folding/Non-Sterile/Sterile/Sterilization) يتم عبر محرّر القوالب القائم (إضافة/تعديل البنود) — استخدمت قوالب v13 الموجودة ورقم النموذج/الإصدار/التاريخ قابلة للتعديل؛ لم أخترع بنود فحص رسمية لم تصلني نصوصها.
- **الوحدات الطبيعية**: سندات طي قديمة بوحدة «باكت» (من v14) تظهر كتنبيه ليُعدَّل كل سند (لم أحوّلها تلقائيًا).
